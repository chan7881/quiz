# 수업 실시간 퀴즈

카훗처럼 쓰는 실시간 퀴즈. 학생은 **코드만** 넣고 들어온다. 앱 설치도 로그인도 없다.

원에듀(wonedu.org)의 실시간 퀴즈를 역설계해 같은 구조로 만들었다
(→ `..\wonedu-분석\설계_역설계.md`).

```
브라우저 (정적 HTML/JS — 빌드 없음)
   ├─ POST {supabase}/rest/v1/rpc/<함수>    ← 상태·데이터 전부
   └─ WSS  {supabase}/realtime/v1/websocket ← "다시 물어보라" 신호만
```

**애플리케이션 서버가 없다.** 로직 전체가 Postgres 함수 안에 있다.

## 1. Supabase 프로젝트 만들기 (5분, 무료)

1. <https://supabase.com> → **Start your project** → GitHub 또는 이메일로 가입
2. **New project**
   - Name: 아무거나 (예: `quiz`)
   - Database Password: **적어 두세요.** 지금은 안 쓰지만 나중에 필요합니다
   - Region: **Northeast Asia (Seoul)** — 교실에서 빠릅니다
   - Plan: **Free**
3. 만들어지는 데 1~2분 걸립니다.

## 2. SQL 실행

### 2-1. SQL 내용을 손에 넣기

PC 앞이 아니어도 됩니다. 폰에서 이 주소를 열고 **복사 아이콘**을 누르면 전체가 복사됩니다.

<https://github.com/chan7881/quiz/blob/main/sql/schema.sql>

> 원본 텍스트만 보려면 → <https://raw.githubusercontent.com/chan7881/quiz/main/sql/schema.sql>
> (27,000자 정도 됩니다. 중간이 잘리지 않았는지는 2-4에서 확인합니다.)

### 2-2. 편집기 열기

1. 왼쪽 메뉴에서 **SQL Editor** (`>_` 모양 아이콘)
2. 검색창 옆 **`+`** → **Create a new snippet**

> ⚠️ **`Create a new logs query` 가 아닙니다.** 그건 서버 로그를 뒤지는 전용 편집기라
> 우리 SQL이 안 돌아갑니다. `Create a new folder` 는 그냥 정리용 폴더입니다.
> **snippet = 보통의 SQL 질의**입니다.

### 2-3. 붙여넣고 실행

1. 빈 편집기를 한 번 클릭해 커서를 넣습니다
2. **Ctrl+A** 로 전체 선택 (안에 뭐가 있든 지우려는 것 — 비어 있어도 해가 없습니다)
3. **Ctrl+V** 로 붙여넣기
4. **Ctrl+Enter** (또는 오른쪽 아래 **Run** 단추)

경고창이 뜰 수 있습니다 — `alter table` · `revoke` 가 들어 있어서 Supabase 가
"되돌릴 수 없는 작업일 수 있다"고 묻는 것입니다. **새 프로젝트라 지울 것이 없으니
그대로 진행하면 됩니다.**

### 2-4. 됐는지 확인

아래가 나오면 성공입니다.

```
Success. No rows returned
```

눈으로 한 번 더 보려면:

- 왼쪽 **Database → Tables** — `qz_quizzes` · `qz_sessions` · `qz_players` · `qz_answers`
  **네 개**가 보여야 합니다
- 왼쪽 **Database → Functions** — `qz_` 로 시작하는 함수가 **20개**

### 2-5. 오류가 나면

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `syntax error at or near ...` | 붙여넣기가 중간에 잘렸을 가능성이 큽니다 | 편집기 맨 끝이 `-- 이 설계는 DB 에서 broadcast 를…` 로 끝나는지 확인하고, 아니면 다시 복사해 붙여넣기 |
| `permission denied` | 드문 경우 | 메시지를 그대로 알려 주세요 |
| 그 외 | — | 메시지를 **그대로** 알려 주세요 |

> **다시 실행해도 안전합니다.** 전부 `create or replace` / `if not exists` 라
> 몇 번을 돌려도 같은 상태가 됩니다. 중간에 실패했으면 고친 뒤 **통째로 다시** Run 하세요.
> 부분만 다시 돌릴 필요가 없습니다.

## 3. 열쇠 두 개를 `config.js` 에 넣기

왼쪽 메뉴 **Settings**(톱니) → **API Keys** (또는 위쪽 **Connect** 단추).

**① Project URL** → `config.js` 의 `url`
`https://<영문 20자>.supabase.co` 모양입니다.

**② 공개 키** → `config.js` 의 `anonKey`
Supabase 가 키 체계를 바꾸는 중이라 **화면에 둘 중 하나가 보입니다. 어느 쪽이든 됩니다.**

| 보이는 것 | 생김새 | 비고 |
|---|---|---|
| `anon` `public` (구) | `eyJhbGci…` | 2026년 말까지만 |
| `Publishable key` (신) | `sb_publishable_…` | 앞으로 쓸 것 |

> 코드가 둘 다 받게 돼 있습니다. 새 키는 JWT 가 아니라서 `Authorization: Bearer` 로
> 보내면 거절되는데, `js/shell.js` 가 **키가 JWT 일 때만** 그 헤더를 붙입니다.

**③ 넣기** — `config.js` 를 열어 `PASTE_PROJECT_URL` · `PASTE_ANON_KEY` 자리에 붙여넣습니다.

> ⚠️ **`service_role` 키와 `sb_secret_…` 키는 절대 넣지 마세요.** 그 키는 모든 테이블을
> 통째로 엽니다. 화면에서 **Reveal** 을 눌러야 보이는 것은 전부 비밀 키라고 생각하세요.
>
> 공개 키가 브라우저에 보이는 것은 **정상입니다** — 이 키로는 테이블을 못 만지고,
> `schema.sql` 이 열어 둔 함수 15개만 부를 수 있습니다. 이 리포가 공개라서
> 키가 인터넷에 노출되지만 설계상 문제가 없습니다.

## 4. 띄우기

**내 PC에서 시험할 때**

```powershell
cd "$env:USERPROFILE\Desktop\Claude\실시간퀴즈"
python -m http.server 8777 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:8777/>

> `file://` 로 직접 열면 안 됩니다. 반드시 서버로 띄우세요.

**학생들이 쓰게 하려면** — 이 폴더를 통째로 GitHub Pages 나 Cloudflare Pages 에 올리면
끝입니다. 빌드 과정이 없어서 파일 그대로 올라가면 됩니다.

## 5. 수업에서 쓰는 순서

**미리 (교무실에서)**

1. 첫 화면 → **퀴즈 만들기 · 진행하기**
2. **+ 새 퀴즈** → 제목 · 참여 방식 · 문항 작성 → **저장**

**참여 방식 두 가지**

| | 별명 | 번호·이름 |
|---|---|---|
| 준비 | 없음 | 명단을 붙여넣어야 함 |
| 학생 입력 | 별명 자유 | 자기 번호 선택 |
| 점수판 | 별명 표시 | `3 박도윤` 표시 |
| 언제 | 아무 반이나 즉석에서 | 형성평가 기록으로 남길 때 |

명단은 한 줄에 `번호 이름` 으로 붙여넣습니다. `1 김민준` · `1,김민준` · `1. 김민준` 다 됩니다.

**수업 중**

1. 목록에서 **진행** → 여섯 글자 코드가 크게 뜹니다. 칠판에 적거나 화면에 띄우세요
2. 학생들이 들어오면 **시작하기**
3. 문항 → 시간이 끝나거나 **답 공개하기** → **점수판 보기** → **다음 문항**
4. 마지막에 **결과 자세히 보기** — 문항별 정답률과 학생별 점수가 표로 나옵니다

**수업 뒤** — **수업 끝내기**를 누르면 코드가 풀려 다음에 재사용됩니다.
누르지 않아도 다음에 **진행**을 누르면 옛 세션은 자동으로 닫힙니다.

## 6. 문항 9유형

| 갈래 | 유형 | 정답 | 점수 |
|---|---|---|---|
| 지식 확인 | 객관식 · 진실/거짓 · 여러 개 선택 | 보기에서 지정 | O |
| | 답변 입력 | 글자 (띄어쓰기·대소문자 무시) | O |
| | 슬라이더 | 숫자 ± 오차 | O |
| 의견 수집 | 설문 조사 · 규모 · 단어 클라우드 · 서술형 | 없음 | X |

- **빨리 맞힐수록 높은 점수**를 켜면 배점의 절반이 속도로 갑니다. 늦어도 0점은 아닙니다
- 그림·영상은 **주소만** 받습니다. 유튜브 주소를 넣으면 영상으로 들어갑니다

## 7. 이 설계가 지키는 것

- **문항이 열려 있는 동안 서버는 정답도 점수판도 안 준다.** 개발자 도구를 열어도 안 새게
  막는 자리는 서버뿐입니다. 학생 화면으로 가는 문항은 `qz_strip()` 을 반드시 거칩니다
- **교사 화면은 빔프로젝터에 뜬다.** 서버는 교사에게 정답을 주지만, 그리는 것은 공개 단계부터입니다
- **첫 응답만 남는다.** `(session, ord, guest)` 가 기본키라 중복 제출이 DB 수준에서 막힙니다
- **진행 중 편집이 수업을 흔들지 않는다.** 진행을 시작하면 문항이 세션으로 복사됩니다
- **실시간이 끊겨도 굴러간다.** 브로드캐스트는 "다시 물어보라"는 신호일 뿐이고,
  5초 폴링이 소켓이 살아 있어도 같이 돕니다. 교실 와이파이를 믿지 않는 설계입니다

## 8. 검사

```powershell
node test\edit.test.js      # 44개 — 명렬 파싱 · 링크 스킴 · 유형 전환 · 저장 전 검증 (오프라인)
node test\e2e.js            # 43개 — 진짜 Supabase 를 상대로 교사·학생 한 바퀴
```

`e2e.js` 는 **기능이 도는지만 보지 않습니다.** 새면 안 되는 것이 안 새는지도 봅니다 —
문항이 열려 있는 동안 학생 응답에 `answer` 키가 아예 없는지, 응답 분포가 안 나가는지,
점수판 호출이 거절되는지, 중복 제출로 점수가 오르지 않는지. 끝나면 만든 퀴즈를 지웁니다
(남기려면 `$env:KEEP=1`).

링크 스킴 검사(`safeLink`)는 **변이 검사로 확인했습니다** — 정규식의 `^` 를 빼면
두 개가 실패합니다. 실패하지 않으면 검사가 없는 것과 같습니다.

화면 색은 라이트·다크 **두 모드에서 실측**해 전부 4.5:1 이상입니다.

## 9. 확인한 것 · 아직 못 한 것 · 없는 것

**확인함 (2026-08-26)**

- `sql/schema.sql` 이 실제 Postgres 에서 돕니다. 테이블 4개 · 함수 20개
- 서버 한 바퀴 43개 통과 (`node test\e2e.js`) — 저장·진행·참여·채점·점수판·보고서·종료

**아직 못 함**

- ⚠️ **브라우저에서 사람이 실제로 눌러 본 적이 없습니다.** 서버는 검증됐지만
  화면 배선(클릭 → RPC)은 아직입니다. 첫 수업 전에 반드시 한 번 돌려 보세요
- ⚠️ **여러 명이 동시에 붙는 상황을 안 봤습니다.** 실시간 소켓은 두 대 이상이라야 압니다

**없는 것**: AI 문항 생성 · 팀전 · 문항 은행 · 다른 기기에서 내 퀴즈 보기
  (퀴즈 소유권이 **이 브라우저에만** 저장되는 토큰이라, 교무실 PC에서 만든 것은
  교실 PC에서 안 보입니다. 필요하면 로그인을 붙여야 합니다)
