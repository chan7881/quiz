# 수업 실시간 퀴즈

카훗처럼 쓰는 실시간 퀴즈. 학생은 **코드만** 넣고 들어온다. 앱 설치도 로그인도 없다.

원에듀(wonedu.org)의 실시간 퀴즈를 역설계해 같은 구조로 만들었다
(→ `..\wonedu-분석\설계_역설계.md`).

```
브라우저 (정적 HTML/JS — 빌드 없음)
   ├─ POST {supabase}/rest/v1/rpc/<함수>    ← 상태·데이터 전부
   └─ WSS  {supabase}/realtime/v1/websocket ← "다시 물어보라" 신호만
```

**애플리케이션 서버가 없다.** 로직 전체가 Postgres 함수 안에 있다.

---

## 1. Supabase 프로젝트 만들기 (5분, 무료)

1. <https://supabase.com> → **Start your project** → GitHub 또는 이메일로 가입
2. **New project**
   - Name: 아무거나 (예: `quiz`)
   - Database Password: **적어 두세요.** 지금은 안 쓰지만 나중에 필요합니다
   - Region: **Northeast Asia (Seoul)** — 교실에서 빠릅니다
   - Plan: **Free**
3. 만들어지는 데 1~2분 걸립니다.

## 2. SQL 실행

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. `sql/schema.sql` 을 **통째로** 복사해 붙여넣고 **Run** (Ctrl+Enter)
3. `Success. No rows returned` 이 나오면 된 겁니다.

> 다시 실행해도 안전합니다(전부 `create or replace` / `if not exists`).
> 고칠 일이 생기면 파일을 고쳐서 통째로 다시 Run 하면 됩니다.

## 3. 열쇠 두 개를 `config.js` 에 넣기

1. 왼쪽 메뉴 **Settings**(톱니) → **API**
2. 두 값을 복사합니다.
   - **Project URL** → `url`
   - **Project API keys** 의 **`anon` `public`** → `anonKey`
3. `config.js` 를 열어 `PASTE_...` 자리에 붙여넣습니다.

> ⚠️ **`service_role` 키는 절대 넣지 마세요.** 그 키는 모든 테이블을 통째로 엽니다.
> `anon` 키가 브라우저에 보이는 것은 정상입니다 — 이 키로는 테이블을 못 만지고,
> `schema.sql` 이 열어 둔 함수 15개만 부를 수 있습니다.

## 4. 띄우기

**내 PC에서 시험할 때**

```powershell
cd "$env:USERPROFILE\Desktop\Claude\실시간퀴즈"
python -m http.server 8777 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:8777/>

> `file://` 로 직접 열면 안 됩니다. 반드시 서버로 띄우세요.

**학생들이 쓰게 하려면** — 이 폴더를 통째로 GitHub Pages 나 Cloudflare Pages 에 올리면
끝입니다. 빌드 과정이 없어서 파일 그대로 올라가면 됩니다.

## 5. 수업에서 쓰는 순서

**미리 (교무실에서)**

1. 첫 화면 → **퀴즈 만들기 · 진행하기**
2. **+ 새 퀴즈** → 제목 · 참여 방식 · 문항 작성 → **저장**

**참여 방식 두 가지**

| | 별명 | 번호·이름 |
|---|---|---|
| 준비 | 없음 | 명단을 붙여넣어야 함 |
| 학생 입력 | 별명 자유 | 자기 번호 선택 |
| 점수판 | 별명 표시 | `3 박도윤` 표시 |
| 언제 | 아무 반이나 즉석에서 | 형성평가 기록으로 남길 때 |

명단은 한 줄에 `번호 이름` 으로 붙여넣습니다. `1 김민준` · `1,김민준` · `1. 김민준` 다 됩니다.

**수업 중**

1. 목록에서 **진행** → 여섯 글자 코드가 크게 뜹니다. 칠판에 적거나 화면에 띄우세요
2. 학생들이 들어오면 **시작하기**
3. 문항 → 시간이 끝나거나 **답 공개하기** → **점수판 보기** → **다음 문항**
4. 마지막에 **결과 자세히 보기** — 문항별 정답률과 학생별 점수가 표로 나옵니다

**수업 뒤** — **수업 끝내기**를 누르면 코드가 풀려 다음에 재사용됩니다.
누르지 않아도 다음에 **진행**을 누르면 옛 세션은 자동으로 닫힙니다.

## 6. 문항 9유형

| 갈래 | 유형 | 정답 | 점수 |
|---|---|---|---|
| 지식 확인 | 객관식 · 진실/거짓 · 여러 개 선택 | 보기에서 지정 | O |
| | 답변 입력 | 글자 (띄어쓰기·대소문자 무시) | O |
| | 슬라이더 | 숫자 ± 오차 | O |
| 의견 수집 | 설문 조사 · 규모 · 단어 클라우드 · 서술형 | 없음 | X |

- **빨리 맞힐수록 높은 점수**를 켜면 배점의 절반이 속도로 갑니다. 늦어도 0점은 아닙니다
- 그림·영상은 **주소만** 받습니다. 유튜브 주소를 넣으면 영상으로 들어갑니다

---

## 7. 이 설계가 지키는 것

- **문항이 열려 있는 동안 서버는 정답도 점수판도 안 준다.** 개발자 도구를 열어도 안 새게
  막는 자리는 서버뿐입니다. 학생 화면으로 가는 문항은 `qz_strip()` 을 반드시 거칩니다
- **교사 화면은 빔프로젝터에 뜬다.** 서버는 교사에게 정답을 주지만, 그리는 것은 공개 단계부터입니다
- **첫 응답만 남는다.** `(session, ord, guest)` 가 기본키라 중복 제출이 DB 수준에서 막힙니다
- **진행 중 편집이 수업을 흔들지 않는다.** 진행을 시작하면 문항이 세션으로 복사됩니다
- **실시간이 끊겨도 굴러간다.** 브로드캐스트는 "다시 물어보라"는 신호일 뿐이고,
  5초 폴링이 소켓이 살아 있어도 같이 돕니다. 교실 와이파이를 믿지 않는 설계입니다

## 8. 검사

```powershell
node test\edit.test.js      # 44개 — 명렬 파싱 · 링크 스킴 · 유형 전환 · 저장 전 검증
```

링크 스킴 검사(`safeLink`)는 **변이 검사로 확인했습니다** — 정규식의 `^` 를 빼면
두 개가 실패합니다. 실패하지 않으면 검사가 없는 것과 같습니다.

화면 색은 라이트·다크 **두 모드에서 실측**해 전부 4.5:1 이상입니다.

---

## 9. 아직 확인 못 한 것 · 없는 것

- ⚠️ **`sql/schema.sql` 은 아직 실제 Postgres 에서 실행해 보지 않았습니다.**
  구문 구조(괄호·`$fn$` 짝)만 확인했습니다. 2단계에서 오류가 나면 그대로 알려 주세요
- ⚠️ **학생↔교사 한 바퀴를 실제로 돌려 보지 않았습니다.** Supabase 가 붙어야 가능합니다
- 없는 것: AI 문항 생성 · 팀전 · 문항 은행 · 다른 기기에서 내 퀴즈 보기
  (퀴즈 소유권이 **이 브라우저에만** 저장되는 토큰이라, 교무실 PC에서 만든 것은
  교실 PC에서 안 보입니다. 필요하면 로그인을 붙여야 합니다)
