# 수업 실시간 퀴즈

카훗처럼 쓰는 실시간 퀴즈. 학생은 **코드만** 넣고 들어온다. 앱 설치도 로그인도 없다.

원에듀(wonedu.org)의 실시간 퀴즈를 역설계해 같은 구조로 만들었다
(→ `Desktop\Claude\wonedu-분석\설계_역설계.md`, 원본 소스 사본은 같은 폴더 `live\`).

```
브라우저 (정적 HTML/JS — 빌드 없음)
   ├─ POST {supabase}/rest/v1/rpc/<함수>    ← 상태·데이터 전부
   └─ WSS  {supabase}/realtime/v1/websocket ← "다시 물어보라" 신호만
```

**애플리케이션 서버가 없다.** 로직 전체가 Postgres 함수 안에 있다.

## 5. 수업에서 쓰는 순서

**맨 처음 한 번 — 열쇠 문구 정하기** ★

퀴즈는 서버에 저장되지만, **"내 것"이라는 증명(열쇠)은 브라우저에** 있습니다.
그대로 두면 교무실 PC에서 만든 퀴즈가 교실 PC에서는 안 보이고,
브라우저 데이터를 지우면 영영 못 엽니다.

목록 화면 아래에 카드가 **두 장** 있습니다. 하는 일이 달라서 나눠 두었습니다.

| 카드 | 언제 | 하는 일 |
|---|---|---|
| **다른 기기에서 만든 퀴즈 불러오기** | 교실 PC·폰에서 | 그 문구에 퀴즈가 **있는지 먼저 확인**하고, 있을 때만 불러옵니다 |
| **이 기기의 열쇠 문구 정하기** | 교무실에서 처음 한 번 | 이 기기의 열쇠를 그 문구로 정합니다 (있던 퀴즈도 함께 옮길 수 있어요) |

예: `우리학교 홍길동 과학 2026` — 학교·이름·과목·연도를 섞으면 짓기도 외우기도 쉽습니다.

**불러오기는 안전합니다.** 문구가 틀리면 「그 문구로 저장된 퀴즈가 없어요」라고만 하고
**이 기기의 열쇠를 건드리지 않습니다.** 맞으면 「퀴즈 3개를 불러왔어요」처럼 개수를 알려 줍니다.

> 띄어쓰기·대소문자는 알아서 맞춰 줍니다. 한글이 기기마다 다르게 저장되는 문제
> (윈도우 NFC / 맥·iOS NFD)도 처리하므로, **눈에 같아 보이면 같은 문구로 취급**합니다.

> ⚠️ 문구를 아는 사람은 내 퀴즈를 열고 고칠 수 있습니다. **이름·학교·연도를 섞어** 길게
> 지으세요(8자 이상). 문구는 브라우저 밖으로 나가지 않고, 그 해시(SHA-256)만 열쇠로 씁니다.

**미리 (교무실에서)**

1. 첫 화면 → **퀴즈 만들기 · 진행하기**
2. **+ 새 퀴즈** → 제목 · 참여 방식 · 문항 작성 → **저장**

**참여 방식 두 가지**

| | 별명 | 번호·이름 |
|---|---|---|
| 준비 | 없음 | 명단을 붙여넣어야 함 |
| 학생 입력 | 별명 자유 | 자기 번호 선택 |
| 점수판 | 별명 표시 | `3 박도윤` 표시 |
| 언제 | 아무 반이나 즉석에서 | 형성평가 기록으로 남길 때 |

명단은 한 줄에 `번호 이름` 으로 붙여넣습니다. `1 김민준` · `1,김민준` · `1. 김민준` 다 됩니다.

**수업 중**

1. 목록에서 **진행** → **QR 코드**와 여섯 글자 코드가 함께 뜹니다.
   화면에 띄우면 학생들이 **폰 카메라로 찍어** 바로 들어옵니다
   (코드를 잘못 치는 일이 사라집니다). 카메라가 안 되는 학생은 코드를 넣으면 됩니다
2. 학생들이 들어오면 **시작하기**
3. 문항 → 시간이 끝나거나 **답 공개하기** → **점수판 보기** → **다음 문항**
4. 마지막에 **결과 자세히 보기** — 문항별 정답률과 학생별 점수가 표로 나옵니다

**수업 뒤** — **수업 끝내기**를 누르면 코드가 풀려 다음에 재사용됩니다.
누르지 않아도 다음에 **진행**을 누르면 옛 세션은 자동으로 닫힙니다.

## 5-1. ⚠️ 무료 Supabase 는 **1주일 놀면 잠긴다**

무료 프로젝트는 **1주일 동안 아무 요청이 없으면 자동으로 일시정지**됩니다.
학교에는 방학이 있으니, 그냥 두면 개학 첫날 수업 직전에 「앱이 안 열린다」가 됩니다.

그래서 **주 3회(월·수·금) 자동으로 깨웁니다** — `.github/workflows/keepalive.yml`.
GitHub Actions 가 가벼운 조회 하나를 보내고, 응답이 없으면 **일부러 실패해서 메일로 알립니다.**
조용히 멈춰 있다가 수업 날 발견하는 최악을 막는 알람입니다.

- 손으로 돌려 보려면: 저장소 **Actions → Supabase 깨우기 → Run workflow**
- ⚠️ GitHub 은 **저장소에 60일 동안 활동이 없으면 예약 작업을 끕니다.**
  끄기 전에 메일이 오고, Actions 탭에서 다시 켜면 됩니다(커밋을 하나 하면 60일이 초기화).
- 이미 잠겼다면: Supabase 대시보드에서 **Restore**. 잠긴 뒤 **90일 안**이면 복구됩니다.

> 근본 해결은 Pro($25/월)입니다 — 유료 프로젝트는 일시정지되지 않습니다.

> ⚠️ **지금 상태(2026-10-09): 프로젝트가 잠겨 있고 깨우기 예약은 꺼 두었다.**
> 프로젝트 주소(`gzujnpbwcodppfmwmiwf.supabase.co`)가 DNS에서 사라졌다(마지막 깨우기 성공 09-02).
> 다시 쓰려면 ① 대시보드에서 **Restore**(90일 기한 — 대략 12월 초까지) ② `keepalive.yml`의 `schedule` 주석을 푼다.
> **메일 알람만 믿지 말 것** — 상태는 로그인 없이 이렇게 본다:
> `Invoke-RestMethod 'https://api.github.com/repos/chan7881/quiz/actions/runs?per_page=5'`

## 7. 이 설계가 지키는 것

- **문항이 열려 있는 동안 서버는 정답도 점수판도 안 준다.** 개발자 도구를 열어도 안 새게
  막는 자리는 서버뿐입니다. 학생 화면으로 가는 문항은 `qz_strip()` 을 반드시 거칩니다
- **교사 화면은 빔프로젝터에 뜬다.** 서버는 교사에게 정답을 주지만, 그리는 것은 공개 단계부터입니다
- **첫 응답만 남는다.** `(session, ord, guest)` 가 기본키라 중복 제출이 DB 수준에서 막힙니다
- **진행 중 편집이 수업을 흔들지 않는다.** 진행을 시작하면 문항이 세션으로 복사됩니다
- **실시간이 끊겨도 굴러간다.** 브로드캐스트는 "다시 물어보라"는 신호일 뿐이고,
  5초 폴링이 소켓이 살아 있어도 같이 돕니다. 교실 와이파이를 믿지 않는 설계입니다
- **브로드캐스트는 교사 브라우저가 직접 쏩니다**(DB가 아님). 그래서 RLS·`realtime.send()` 버전 의존이 없습니다.
  페이로드는 비어 있고, 정본은 언제나 `qz_state()` 입니다. 서버 함수는 전부 `SECURITY DEFINER` 입니다

## 8. 검사

```powershell
node test\edit.test.js      # 53개 — 명렬 파싱 · 링크 스킴 · 유형 전환 · 저장 전 검증 (오프라인)
node test\phrase.test.js    # 14개 — 열쇠 문구 → 열쇠 (기기가 달라도 같은가)
node test\e2e.js            # 43개 — 진짜 Supabase 를 상대로 교사·학생 한 바퀴
```

QR 검사는 파이썬 쪽 도구가 필요합니다(기준 인코더 `segno` + 디코더 `opencv`).

```powershell
python -m venv qrenv
qrenv\Scripts\pip install segno opencv-python-headless numpy
qrenv\Scripts\python test\qr_check.py       # 7개 — 배율·흐림·여백을 바꿔 가며 실제로 읽히는가
qrenv\Scripts\python test\qr_svg_check.py   # 3개 — SVG 로 그린 결과를 되짚어 디코딩
```

> QR 은 **바깥 라이브러리 없이** `js/qr.js` 가 직접 만듭니다 — CDN 을 쓰면 학교 와이파이가
> 막거나 느린 그 순간 수업이 멈추기 때문입니다. 그래서 «눈으로 보니 QR 같다» 로는 부족하고,
> **실제로 디코딩되는지**를 판정 기준으로 삼습니다.

`e2e.js` 는 **기능이 도는지만 보지 않습니다.** 새면 안 되는 것이 안 새는지도 봅니다 —
문항이 열려 있는 동안 학생 응답에 `answer` 키가 아예 없는지, 응답 분포가 안 나가는지,
점수판 호출이 거절되는지, 중복 제출로 점수가 오르지 않는지. 끝나면 만든 퀴즈를 지웁니다
(남기려면 `$env:KEEP=1`).

링크 스킴 검사(`safeLink`)는 **변이 검사로 확인했습니다** — 정규식의 `^` 를 빼면
두 개가 실패합니다. 실패하지 않으면 검사가 없는 것과 같습니다.

화면 색은 라이트·다크 **두 모드에서 실측**해 전부 4.5:1 이상입니다.
